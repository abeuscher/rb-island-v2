# Session 009 — Bot Opponent — Brief

**Type:** feature
**Shape:** plan-backed
**Branch:** session-009

## Goal

A player can start and play a full match against a bot opponent — no second human
required — with the bot making real per-round decisions through its own fog, across
three difficulty presets.

## Plan reference

This session executes the plan file's entry for **Bot opponent** (`sessions/plan.md`).
Read that entry first — it is canonical for scope, success criterion, prerequisites, and
artifact.

## Session-specific deltas

- This is not the same thing as `PracticeController.luau`'s scripted dummy (Sessions
  006-008): the dummy is non-adaptive by design (one fixed cannon, one fixed shot,
  forever) and was always meant to be a placeholder, not the bot. Whether the bot
  replaces the dummy inside `PracticeController`, or `PracticeController` stays exactly
  as-is and the bot becomes a third way into a match (alongside "Start Game" and
  "Practice vs. Dummy" on the Intro screen), is this session's first real decision —
  worth raising at the Open Gate.
- `sim/archetypeKit.luau` and `sim/archetypes/*.luau` (five of them, from Session 003)
  are already exactly the shape §14 asks for: a pure `decide(config, view) -> commands`
  strategy reading only a `src/shared/view.luau` `View` — candidate-cell search, spread
  placement, belief-map queries, and legal-target selection all already exist in
  `archetypeKit.luau`. Read these before writing anything new; the bot's opening/probe/
  suppress/kill/rebuild behavior may be substantially assemblable from what's already
  there rather than written from scratch. None of it has ever run outside the sim
  harness, so check it still holds up against `rules.luau`'s current contract.
- Where the bot's decisions plug in is a real design question, not a detail: does it get
  a seat in `server/MatchService.luau`'s round loop (as a non-networked stand-in for the
  second `Player`, deciding once per PLAN phase the way `sim/harness.luau` already
  drives an archetype), or does it run its own separate local flow outside `MatchService`
  entirely? `MatchService` currently assumes exactly two real `Player` Instances in
  `self.players` — worth reading in full before deciding how a bot without a `Player`
  Instance fits (or doesn't).
- Difficulty presets (Shoal/Skirmish/Siege, §14) need a place to be chosen before a
  match starts — there's no such control yet anywhere in the UI (Settings' registry is
  still empty).

## Starting state

- Two real Studio clients can matchmake, complete setup, and play a full match against
  each other with the server holding all authoritative state (Session 008, user-
  confirmed live).
- `PracticeController.luau` still offers offline solo play against the old scripted
  dummy (fixed cannon, fixed shot) — unaffected by this session unless the first delta
  above resolves toward replacing it.
- Five scripted archetype strategies already exist and are exercised daily by
  `lune run sim`/`lune run sweep`, but have never been wired into a real playable match.
- The housekeeping inbox is empty; nothing to absorb this session.

## Open questions

- Does the bot replace `PracticeController`'s dummy, or sit alongside it as a third
  match-start option? (See first delta above.)
- Does the bot get a seat in `MatchService`'s round loop, or run its own parallel flow?
  (See third delta above.)
- Worth deciding at the Open Gate rather than defaulting either way, since both are
  cross-cutting enough to be expensive to reverse once half-built.
