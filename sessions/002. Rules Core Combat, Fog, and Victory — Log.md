# Session 002 — Rules Core Combat, Fog, and Victory — Log

**Date:** 2026-09-17
**Branch:** main
**Type:** feature

## What was built

### Phase 1 — Line of flight (`src/shared/flight.luau`)

- `Flight.chebyshevDistance`, `Flight.range` (shared formula for both fire modes — a
  weapon's own `elevation_range_bonus` and `range` fields already reduce correctly for
  arc fire, which has bonus 0), and `Flight.resolveShot`.
- Direct fire walks an evenly-stepped beam (`t = step / Chebyshev distance`) and blocks
  strictly above the interpolated beam height, per §10's grazing rule. Arc fire ignores
  terrain entirely and always connects if in range.

### Phase 2 — Fog of war (`src/shared/fog.luau`)

- Belief maps are a flat, copy-on-write table keyed by cell. `Fog.applyReveal` records
  either a live/under-construction structure, empty land, or rubble (if the cell was
  destroyed that same round) — never live-updated except by an actual reveal.
- Cannon reveals mark the full beam path plus impact; mortar reveals mark the impact cell
  and its four orthogonal neighbors.

### Phase 3 — Round resolution and victory (`src/shared/rules.luau`)

- `Rules.resolveRound(config, state, commandsA, commandsB)` validates each side's whole
  command batch together — this is where §8's same-round terrain-edit/placement
  interaction (deferred from Session 001) finally gets enforced — then runs the fixed
  RESOLVE order from §4: terrain edits, construction completion, simultaneous volley
  resolution, damage/destruction, fog reveals, income accrual, incapacitation-streak
  update, victory check.
- Both players' volleys are resolved from the same pre-volley structures snapshot, so
  neither side's fire is affected by damage the other side lands this round — a weapon
  destroyed this round still gets its shot off, and both bases can fall in the same
  resolve.
- All four victory conditions from §5: base elimination (including simultaneous mutual
  elimination, decided on points), incapacitation with the grace-round window, the round
  limit, and the full points/tiebreak chain (score → fewest structures lost → fewest
  rounds elapsed → draw).
- `state.luau` gained `belief`, `destructionPoints`, `structuresLost`, and
  `incapableStreak` per player, plus an exported `State.withPlayer` that merges fields
  onto existing player state instead of replacing it wholesale (the replace-wholesale
  version would have silently dropped these new fields on every terrain/structure
  command).
- `structures.luau` gained `Structures.damage` — applies to any structure regardless of
  construction state, since half HP under construction is a vulnerability, not immunity.
- `config.luau` gained `MAX_ROUNDS`, `INCAPACITATION_GRACE_ROUNDS`, and the `POINTS` table
  from §5.4, none of which existed yet.

### Phase 4 — A bug fix along the way

- Session 001's `State.placeStructure` spent a structure's `energy_cost` at build time as
  well as its `supply_cost`. That field is the per-shot firing cost from §8's behavior
  text, not a second build cost — the scripted-match test surfaced it (a cannon's owner
  came up short on Energy it had clearly already paid for). Fixed: placement now spends
  Supply only.

Six decisions logged in `DECISIONS.md`: the beam-fraction distance metric, the new
`POINTS` table, rubble as a stale belief-map entry (resolves §18's open question on
rubble persistence), mutual simultaneous incapacitation decided by points (extending the
mutual-base-elimination precedent), `resolveRound`'s config-first signature, and the
Energy-cost build fix above.
