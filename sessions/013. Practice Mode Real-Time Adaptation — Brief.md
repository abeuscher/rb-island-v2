# Session 013 — Practice Mode Real-Time Adaptation — Brief

**Type:** feature
**Shape:** plan-backed
**Branch:** session-013

## Goal

Rework `src/client/UI/PracticeController.luau` (the offline "Practice vs. Dummy" flow) to
drive `Rules.applyCommand`/`Rules.tick` the same way the real networked path now does,
instead of its own inline copy of the deleted round-batch `resolveRound` model.

## Plan reference

This session executes the plan file's entry for **Practice mode real-time adaptation**
(`sessions/plan.md`). Read that entry first — it is canonical for scope, success criterion,
prerequisites, and artifact.

## Session-specific deltas

- This entry was chosen over three other equally-unblocked entries ("Client real-time UI,"
  "Bot re-adaptation," "Sim harness rewrite" — see session 012's log) because it's the
  smallest, clearest scope, and because restoring a single-client test path matters now:
  session 012's real-time bug (setup bases never going live) only surfaced through a live
  two-Studio-client test, which is slow to iterate on. A working Practice mode gives a much
  faster loop for exactly that kind of check going forward.
- `PracticeController.luau` currently reimplements, inline, almost everything session 012
  moved into `server/MatchService.luau` and `src/shared/tickView.luau`: command application,
  a recurring per-round resolve step, and its own copy of the shot/destroyed redaction logic
  `resolveView.luau` used to hold. The natural shape for this session is to make
  `PracticeController.luau` look structurally like `MatchService.luau` minus the network layer
  — a local `Rules.applyCommand` call per player action, a local recurring tick loop (driven by
  `RunService.Heartbeat` accumulating to `config.TICK_SECONDS`, since there's no server
  heartbeat to piggyback on here), and `TickView.new` for the animation payload instead of a
  hand-rolled redaction block.
- Session 012 hit a real bug where setup-placed bases never left "under construction" because
  the ordinary tick-gated `State.completeConstruction` was called at the setup → live
  transition, when `elapsed` was still 0. The fix was `State.completeAllConstruction`
  (unconditional, `src/shared/state.luau`) — `PracticeController.luau`'s own setup → plan
  transition (`startRounds()`) has the exact same shape and needs the exact same fix, not a
  rediscovery of it.
- The dummy opponent's behavior (`_dummyCommandsForRound`: one scripted cannon, retargeting
  every round) needs restating in tick terms — most likely "target once, let it fire on its
  own cooldown" rather than "reissue a target command every round," matching how a real
  player's weapons now behave. Confirm this reads the same in Studio as the old
  fire-every-round dummy did (visually, roughly one shot every few seconds) before calling it
  done — an unintentionally much faster or slower dummy would undercut what this mode is for
  (a stable target to test terrain/blocking against).
