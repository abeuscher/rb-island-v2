# Session 005 — Planning Phase — Brief

**Type:** feature
**Shape:** plan-backed

## Goal

Build the plan-phase UI: a build palette to place and bulldoze structures, terrain tools to
edit and reclaim land, a targeting UI to assign weapons, and a round clock with ready-up —
all validated with cost and smoothness rules and clear rejection feedback.

## Starting state

- `src/client/` exists: `Board.luau` renders terrain from the shared board model,
  `Camera.luau` gives an angled top-down scriptable camera bound to a territory, both wired
  through `init.client.luau`. `src/server/` sets `Players.CharacterAutoLoads = false`.
- `init.client.luau` currently seeds a temporary demo elevation bump purely so the renderer
  could be checked visually in Studio before any real terrain edits existed. This session's
  terrain tools should make that seed unnecessary — remove it once a real edit can be driven
  from the UI instead.
- No server-authoritative match state exists yet — `src/shared/state.luau`'s pure
  `MatchState` model isn't wired into Studio at all. Real client/server networking is a
  later plan entry (**Real two-player networking**).
- The housekeeping inbox is empty; nothing to absorb this session.

## Open questions

- Whether this session's UI drives a local-only `MatchState` held in a LocalScript
  (mirroring **Board in Studio**'s client-only precedent, simplest to build against right
  now) or pulls forward a minimal server-authoritative slice early. Flag at the Open Gate —
  local-only is the likely default, but worth deciding explicitly rather than assuming,
  since it shapes how much of this session's work is throwaway once real networking lands.
