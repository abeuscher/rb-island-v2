## Session-specific deltas

- `lune run sim` currently crashes immediately: `sim/harness.luau:73: invalid 'for' limit
  (number expected, got nil)` — almost certainly a round-count/round-based loop bound that no
  longer exists post-Session-011 (mirroring the exact class of bug Session 015 found and fixed
  in `Bot.luau`: stale references to config/view fields the round→time rename removed). Start
  by tracing what `harness.luau:73` actually expects, rather than assuming this brief's guess
  is the real shape of the bug.
- Two new weapon types (missile, scout drone) landed in Session 016, entirely player-facing —
  the sim archetypes don't know about either yet. Whether to fold them into this rewrite or
  leave the archetypes cannon/mortar-only for now (deferring missile/scout sim support to a
  follow-up) is this session's call once the round→time port itself is done — don't let it
  block the rewrite's own success criterion.

## Starting state

- `sim/` has been broken since Session 011 (five sessions ago); this is the first session to
  actually open it back up.
- `server/Bot.luau` hit the identical class of bug (round-keyed references dead since Session
  011) and was fixed in Session 015 — worth reading as a template for what kind of renames to
  expect here, not for reusable code (the bot and the sim archetypes are separate consumers of
  `archetypeKit.luau`).
- Session 016 added `missile`/`scout` to `config.STRUCTURES` — both are fully generic through
  the shared fire pipeline, so nothing in `rules.luau`/`flight.luau`/`fog.luau` needs sim-side
  changes; only the archetype strategies themselves would need to know the types exist, if
  this session decides to scope that in (see deltas above).
