# Session 005 — Planning Phase — Log

**Date:** 2026-09-17
**Branch:** session-005
**Type:** feature

## What was built

### Phase 1 — Local match state and config additions

- Added `PLAN_SECONDS` (45) and `RESOLVE_SECONDS` (10) to `src/shared/config.luau` — needed
  for the round clock and not previously defined there. No other shared-layer file touched;
  this session consumes `state.luau`/`structures.luau`/`economy.luau`/`board.luau` as-is.
- `src/client/UI/PlanController.luau` holds a local-only `MatchState` (`State.new(config)`),
  per the Open Gate decision to go local-only rather than pull forward server
  authority early. Exposes the plan-phase command surface (place, bulldoze, raise,
  lower, reclaim, target, ready/advance-round), each one forwarding straight into the
  matching `state.luau` function and surfacing its `(ok, err)` result to listeners.
- Target assignment has no shared-layer equivalent yet (`rules.luau`'s resolve step doesn't
  consume targets yet) — tracked client-side in the controller, keyed by the firing
  structure's origin cell (`"x,y"`) rather than table identity, since structure table
  references churn across mutations.
- `advanceRound()` (fired by Ready or clock expiry) runs the RESOLVE-phase steps already
  exposed by `state.luau` — `completeConstruction`, `accrueIncome` — and increments the
  round counter. There's no `rules.luau` round-resolution wired in yet and no opponent to
  wait on in this local-only session, so this is as far as "ready up" goes this session.

### Phase 2 — Plan-phase UI (`src/client/UI/`)

- `BuildPalette.luau` — a fixed column of tool buttons (Build Generator/Cannon/Mortar,
  Bulldoze, Raise/Lower Terrain, Reclaim Land) plus a live list of the player's own
  completed weapons with their assigned target (or "unassigned") and a button to arm
  targeting for each. Buttons are always shown regardless of round; the shared validators
  are the single source of truth for what's locked, and their rejection message is what
  surfaces to the player, rather than duplicating unlock-round gating in the UI.
- `RoundClock.luau` — round/phase label, countdown display, and the Ready button.
- `StructureView.luau` — placeholder rendering (colored part + glyph, per §13) for the
  owner's own placed structures and assigned targets. Only ever draws the owner's own board
  — always fully visible to them — so it doesn't need to touch fog/reveal logic.
- `Cursor.luau` — added after the user's initial confirmation: a footprint preview over the
  hovered cell while a build tool is armed (green/red via the same `Structures.canPlace`
  check the palette relies on, so preview and outcome always agree), and a crosshair
  overlay replacing the system cursor while a weapon is armed for targeting.
- `init.luau` mounts all of the above plus the status/feedback label, wires
  `Input.onBoardClick` to `PlanController:handleBoardClick`, and separates full
  state-change re-renders (`onChange`) from cheap per-frame clock ticks (`onTick`) so the
  countdown doesn't force a board/structure rebuild 60 times a second.
- `src/client/Input.luau` — resolves a mouse click/hover to a board cell via a raycast
  against the rendered board, reusing `ClientBoard`'s own cell-to-world math.
- `src/client/init.client.luau` simplified to `PlanUI.mount("A")` + `Camera.start("A")`; the
  temporary demo elevation seed is gone now that the Raise/Lower tools can produce real
  elevation.

### Scope decisions made along the way

- **Local-only MatchState**, confirmed at the Open Gate — mirrors Session 004's
  client-only precedent; will be rebuilt when **Real two-player networking** lands.
- **`base` excluded from the build palette.** Per §8, bases are placed during a setup phase
  that doesn't exist yet (that arrives with **Full match loop and wrapper screens**), not
  bought with Supply during PLAN — so there was nothing sensible to wire it to this session.
- **Target range/line-of-flight validation deferred.** Targeting only validates that the
  target cell is on the enemy island; range and blocking need `flight.luau`, which belongs
  to the next session (**Resolve phase vs. a dummy opponent**) and wasn't in this session's
  reading list.
- Branch drift flagged in Sessions 001–004 (committed to `main` instead of a
  `session-{NNN}` branch) is resolved this session — `session-005` follows
  `sessions/config.md`'s documented `branch-pattern`.

test` stayed green (71 passed, 0 failed) throughout — the only shared-layer change was the

globals (`game`, `script`), not a parse error.

before requesting the cursor highlight and crosshair addition. That follow-up addition
passed the same build/smoke checks but wasn't separately visually re-confirmed in Studio
