# Session 004 — Board in Studio — Log

**Date:** 2026-09-17
**Branch:** main
**Type:** feature

## What was built

### Phase 1 — Rojo wiring (`default.project.json`)

- Added `StarterPlayer/StarterPlayerScripts/Client` synced from `src/client`, and
  `ServerScriptService/Server` synced from `src/server`, alongside the existing
  `ReplicatedStorage/Shared` mapping.

### Phase 2 — Terrain rendering (`src/client/Board.luau`)

- `ClientBoard.build(parent, board)` renders a shared `board.luau` model into a Workspace
  folder: one water-colored plate spanning the whole board, and one `Part` cube per land
  cell, sized to `(elevation + 1) * STUDS_PER_CELL` tall and colored by one of 3 shades per
  elevation level. Geometry always matches the rules-core model since it's built directly
  from `Board.new`/`Board.getCell`, not a parallel representation.
- Accepts an already-built board so callers can render either the real starting state or a
  modified one, rather than always constructing its own.

### Phase 3 — Camera (`src/client/Camera.luau`)

- `Camera.start(owner)` sets an angled top-down (55°) scriptable camera framed on one
  territory's bounds, computed straight from `config.luau` (mirrors `board.luau`'s own
  sideWidth/channel math). Mouse-wheel zoom and WASD/arrow-key pan are clamped to the
  current territory's bounds; Tab swings the framing to the other territory over a short
  lerp.

### Phase 4 — Entry points (`src/client/init.client.luau`, `src/server/init.server.luau`)

- `init.client.luau` (the LocalScript Rojo generates from `src/client`'s `init.client.luau`)
  builds the board into a `Workspace.Board` folder and starts the camera on side "A".
- `init.server.luau` sets `Players.CharacterAutoLoads = false` per §13 — no avatars.
- After the first visual check in Studio showed both islands correctly flat (round 1's real
  starting state, §3, has no elevation yet), `init.client.luau` was extended to seed a
  temporary demo bump — a small pyramid raised to level 2 near the center of each island —
  purely so all 3 elevation shades/heights could be checked against each other in one view.
  Clearly commented as temporary; not part of `Board.luau`'s own logic.

## Verification

`rojo build` ran clean (no errors) after the initial wiring and again after the demo
elevation seed. The user opened the synced place in Studio and confirmed both territories
and the channel were visually distinguishable, and — after the demo seed was added — that
all three elevation levels were clearly distinguishable as stepped, differently colored
cube heights.
