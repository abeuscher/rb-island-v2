# Session 011 — Real-Time Rules Core — Log

**Date:** 2026-09-18
**Branch:** session-011
**Type:** feature

## What was built

### Phase 1 — Reading pass

Worked the brief's reading list in full: the plan file's "Real-time rules core" entry, this
brief, session 010's log, `sessions/proposal.md` §4/§7/§8/§5.2, and `rules.luau`/`state.luau`/
`economy.luau`/`config.luau` in full, plus the three specs they back. Also read
`structures.luau` in full even though the brief's reading list didn't name it directly — its
`unlock_round`/round-threaded `canPlace`/`place` are tightly coupled to `state.luau` and needed
the same time-keyed treatment.

### Phase 2 — config.luau

Replaced every round-keyed constant with a tick/time-keyed one: `TICK_SECONDS` (0.5, the fixed
heartbeat decided in Session 010), `MATCH_SECONDS` (180), `BUILD_SECONDS` (5), a per-weapon
`cooldown_seconds` (5 for both cannon and mortar), `INCAPACITATION_GRACE_SECONDS` (40),
`UNLOCK_TIME` (`terrain_edit`=20, `reclamation`=60, evenly spaced placeholders standing in for
the old round cadence) replacing `UNLOCK_ROUND`, `SUPPLY_PER_SECOND`/
`ENERGY_PER_GENERATOR_PER_SECOND` replacing `SUPPLY_PER_ROUND`/`ENERGY_PER_GENERATOR`. Split out
a new `STARTING_SUPPLY` (10) — the old code reused `SUPPLY_PER_ROUND` for both the per-round
accrual amount and the opening balance (a Session 001 `DECISIONS.md` call), which no longer
works once the accrual constant is a tiny per-second rate. `STRUCTURES[...].unlock_round`
became `unlock_time` (seconds) for every roster entry.

### Phase 3 — economy.luau and structures.luau

`Economy.accrue` became `Economy.tickAccrue`, scaling both resources by `TICK_SECONDS`;
`Economy.new` now draws its starting Supply from `STARTING_SUPPLY`. `Structures.canPlace`/
`Structures.place` take elapsed match time instead of a round number; `place` now stamps a
`readyAt` timestamp (`elapsed + BUILD_SECONDS`) plus `target`/`nextFireAt` fields on the new
structure; `completeConstruction` only completes a structure once `elapsed >= readyAt`, instead
of unconditionally. Added `Structures.setTarget` for the new persistent per-weapon target.

### Phase 4 — state.luau

`round` became `elapsed`. `incapableStreak` (a round counter) became `incapableSince` — a
nilable timestamp of when a player first became incapable-and-unrecoverable, restating the old
streak in time terms per the brief's delta. Added `State.setTarget`; renamed
`State.accrueIncome` to `State.tickAccrue`.

### Phase 5 — rules.luau

Batch `resolveRound` split in two: `Rules.applyCommand` (place/bulldoze/raise/lower/reclaim/
target, applied immediately and permanently, one at a time — the old "same-round
terrain-edit-blocks-placement" batch-conflict rule was dropped entirely, since with no more
batching there's no simultaneity window left for it to guard against; sequential immediate
application resolves cell conflicts structurally) and `Rules.tick` (one fixed heartbeat:
completes ready construction, resolves automatic weapon fire for both sides against a shared
pre-tick snapshot — same true-simultaneity guarantee as before, just re-run every tick instead
of once per round — accrues income, updates incapacitation-since tracking, checks victory).
Weapon fire is now gated on cooldown (`nextFireAt`) and a persistent target instead of a fresh
per-round target command; `checkVictory`'s old `round_limit` condition is now `time_limit`,
checked against `MATCH_SECONDS`. Scoring, incapacitation math, and the victory-condition
priority order carry over unchanged, restated in time terms.

### Phase 6 — Test rewrite

`economy.spec.luau`, `state.spec.luau`, and `rules.spec.luau` rewritten test-for-test against
the new API (tick-driven combat needed a `fastConfig()` helper in `rules.spec.luau` — shrinking
build time and cannon cooldown to one tick each — so combat tests don't need dozens of `tick()`
calls to see a weapon built and firing). The incapacitation test keeps a short grace window for
the same reason while still exercising the real elapsed-time mechanism, not just its formula.

### Phase 7 — Adjacent shared-layer fallout

Two small fixes outside the brief's named files, needed to keep `lune run test` green:
- `structures.spec.luau`'s `completeConstruction` test needed an `elapsed` argument added
  (signature changed in Phase 3); a wrong assumption in the rewritten `economy.spec.luau` test
  (assumed a per-round-sized increment would trigger the Energy cap; a per-tick increment is
  too small at the values it used) needed its numbers adjusted.
- `view.luau`'s `round` field (consumed by `Bot.luau`/`sim/`, both already out of scope this
  session) renamed to `elapsed`, and `archetypeKit.luau`'s one `view.round` reference updated
  to match — one-line fixes to keep the pure layer and its own tests internally consistent, not
  a redesign of anything in `server/`/`sim/`.
- Deleted `resolveView.luau` and its spec: a per-round batch animation shim (targets resent
  every round, "this round's fire") that's conceptually obsolete once targets persist and fire
  is continuous. The plan file's "MatchService real-time loop" entry already explicitly owns
  redesigning this exact push shape for a continuous tick, so patching it here would only be
  thrown away.
