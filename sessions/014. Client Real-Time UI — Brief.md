# Session 014 — Client Real-Time UI — Brief

**Type:** feature
**Shape:** plan-backed
**Branch:** session-014

## Goal

Rework the client-side plan-phase UI (`RoundClock.luau`, `BuildPalette.luau`, `StructureView.
luau`, `Render.luau`) from a full-rebuild-every-tick model to event-driven rendering, and land
the round-based-UI-to-match-clock cleanup that's been deferred since Session 012's networked
rework.

## Plan reference

## Session-specific deltas

- Session 013 (Practice mode real-time adaptation) surfaced a concrete, confirmed instance of
  this entry's problem, not just the "will look like a flicker" note Session 012 left: `Render.
  luau`'s `onChange` handler calls `renderEnemyBoard()` every tick (every `config.TICK_SECONDS`,
  0.5s), which fully redraws the enemy fog/structure display from the current, already-updated
  belief map. A shot's flight animation takes ~0.9s, so the very next tick's full redraw
  overwrites the beam's progressive per-cell reveal almost immediately — fog now appears to
  reveal instantly on impact instead of tracing in as the shot crosses the board. This is real
  user-visible regression territory (Practice mode used to do this correctly under the old
  round-based model), not cosmetic polish — treat "the enemy board only redraws what changed" as
  load-bearing for this entry's success criterion, not optional follow-on.
- Session 013 also fixed a smaller, related bug in the same handler: `effectsFolder:
  ClearAllChildren()` was being called on every tick too, deleting the in-flight projectile
  itself. That's already fixed (the call was simply removed, since `onResolve` owns clearing
  `effectsFolder` before a new volley) — this session doesn't need to redo it, just build the
  real event-driven reveal on top of a codebase where the projectile itself already survives.
- Both `PlanController.luau` (real networked/bot match) and `PracticeController.luau` (practice)
  share every file this entry touches — a fix here should be verified against both live, not
  just one.
