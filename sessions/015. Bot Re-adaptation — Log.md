### Phase 2 — Round-keyed → time-keyed staleness and unlock checks

`Bot.luau`: `view.round` → `view.elapsed` everywhere it appears (belief-staleness tracking,
both terrain-unlock checks); `config.UNLOCK_ROUND.terrain_edit` → `config.UNLOCK_TIME
.terrain_edit`; `def.unlock_round` → `def.unlock_time`. `beliefSeenRound` renamed
`beliefSeenAt`, now storing elapsed-time timestamps instead of round numbers.
`botDifficulty.luau`: `restProbeRounds` → `restProbeSeconds` (40 / 20 / 10 seconds for
Shoal / Skirmish / Siege — kept the old 4:2:1 ratio, scaled by the ~10s a testing-config round
used to take, per Session 006's log).

### Phase 3 — A second crash bug found on read, outside the brief's own artifact list

`MatchService.luau`'s difficulty-based starting-Supply bonus (`_applyBotSupplyMultiplier`)
multiplied `config.SUPPLY_PER_ROUND`, deleted in the same Session 011 rework — this crashed
any bot match at `_startLive`, independent of everything in `Bot.luau` itself. Swapped for
`config.STARTING_SUPPLY`, keeping the same "extra = base × (multiplier − 1)" shape against the
nearest constant that still means a one-time starting-Supply handicap. Not in the brief's
artifact list, but load-bearing — nothing else in this entry is even reachable without it.

### Phase 4 — Periodic re-decide

Added `config.BOT_DECIDE_INTERVAL_SECONDS` (3s, a guess pending live feel). Replaced
`MatchService`'s single opening `_runBotTurn()` call with a `_botNextDecideAt` timestamp
checked each `_tick()`, re-running `Bot:decide()` on that cadence. `decide()` itself needed no
changes for repeated-call safety — its build/terrain logic already only adds what it doesn't
have (generator-count gate, resource checks, cell reservations), all read fresh off the
current view each call.

`lune run test`: 84/84 (unaffected — all of Phases 2-4 are in `server/`-only files, outside the
pure layer). `rojo build` clean.

### Phase 5 — Single shot by default (user request, mid-session, not this brief's scope)

The user asked for an eventual "autofire" toggle on weapon controls, with single shot as the
default starting now (the toggle itself deferred to whenever the weapon control panel gets
built). This is a real change to the combat model, not a UI tweak: since Session 011, every
targeted weapon has fired automatically on every cooldown. Added `structure.autoFire`
(default `false`) in `structures.luau`; `rules.luau`'s `applyCooldowns` now clears a weapon's
target after it fires unless `autoFire` is set, so firing again needs a fresh target command.
`PracticeController.luau`'s scripted dummy opponent got `autoFire = true` explicitly, since
nothing else ever re-arms it. Updated two `rules.spec.luau` tests that asserted the old
continuous-fire default (one now re-issues a target command between shots; the other sets
`autoFire = true` directly to keep testing the "fires until victory" path) and added a new
test asserting the single-shot default itself. Noted in passing: the bot's own periodic
re-decide (Phase 4) reassigns every live weapon's target on every call regardless of whether
it already has one — this incidentally becomes the bot's own re-arm mechanism under
single-shot, with no extra code needed. `lune run test`: 85/85. `rojo build` clean.

### Phase 6 — Build-menu price and affordability (user request, mid-session)

`BuildPalette.luau`: the three "Build ___" tool buttons (Generator/Cannon/Mortar) now show
their Supply cost right-aligned, and dim (both the label and the price) whenever current
Supply can't cover them — recomputed on every `refresh()`, so it tracks Supply live as it
accrues each tick. Left the buttons clickable while dimmed rather than disabling them, since
Supply changes continuously and the server already rejects an unaffordable placement either
way. `rojo build` clean.

"Weapon inspection and control panel" with a finding: its anticipated `structure.enabled`-style
flag already exists as `structure.autoFire` from Phase 5 above, so that entry's remaining scope
is purely the UI.
