# Session 018 — Scout Drone Reveal Shape — Log

**Date:** 2026-09-18
**Branch:** main
**Type:** feature

## What was built

### Phase 1 — Scout drone reveal shape (the plan entry)

`Fog.revealedCells` now branches on `def.reveal_mode` instead of `def.fire_mode`: `"beam"`
(cannon) and the 5-cell impact cross (mortar/missile, now the default branch) are unchanged;
a new `"scout"` branch reveals a 3-wide corridor from the firing cell to the target plus a 4x4
block anchored on the target. `Flight.beamCells` (previously a private helper inside
`resolveShot`) is now exported so the corridor walk reuses it instead of a second line-walking
algorithm. The corridor widens perpendicular to whichever axis has more steps (the dominant
travel direction) rather than a true geometric perpendicular, so it stays grid-aligned for a
diagonal path — a tie (45°) defaults to widening on y. The 4x4 block has no true center on a
grid, so it's anchored as `x/y ∈ [target-1, target+2]` on both axes.

`Fog.applyReveal` gained an `origin` parameter (the firing cell), threaded through from
`rules.luau` (which already carried `s.origin` per shot, just hadn't passed it) and from
`Render.luau`'s landing-reveal call (`shot.origin`, already present on `tickView.luau`'s shot
shape). `config.STRUCTURES.scout.reveal_mode` changed from `"impact"` to `"scout"`.

Both judgment calls the brief left open (4x4 anchor, diagonal corridor handling) were decided
and documented in `fog.luau`'s comments rather than raised — neither was cross-cutting or hard
to reverse.

### Phase 2 — Scout drone price (user request, live in Studio)

`config.STRUCTURES.scout.supply_cost`: 12 → 4. At 12 it cost as much as a Cannon for a
zero-damage weapon, pricing it out of being worth building; user called it out directly after
playtesting.

### Phase 3 — Restart button fix (user report, found on read)

`PlanController:stopClock()` (the hook `PlanUI.teardown()` calls on every match end/restart)
was a no-op — kept that way under the assumption that, unlike Practice's local heartbeat,
nothing needed cleaning up server-side. That was wrong: `PlanController.new()` opens a
`remotes.StateUpdate.OnClientEvent` connection that was never disconnected. Every restart of an
online or bot match left the previous match's torn-down controller still connected, reacting to
every state push meant for the new match on the same shared remote. `PracticeController` was
never affected — its own `stopClock()` already disconnects its heartbeat correctly. Fixed by
having `PlanController:stopClock()` disconnect and clear `self._stateConn`.

### Phase 4 — Setup base-cap UI (user request)

`Structures.canPlace` never capped base count (only the setup Ready gate did, via
`config.NUM_BASES`), so once 3 bases were placed the "Place Base" tool stayed armed and the
cursor kept showing a valid-looking (green) preview for a base the server would still accept
(nothing stopped a 4th) but that would then block Ready ("place exactly 3 bases") with no clear
indication which extra base to remove. `BuildPalette.luau` now grays out "Place Base" and
auto-switches to Bulldoze once `controller:countOwnBases() >= config.NUM_BASES`, and ignores
clicks on it while maxed — purely a client-side fix, no shared-layer cap added.

### Phase 5 — Weapon/terrain affordability deselect (user request, generalized Phase 4's fix)

Generalized the same pattern to Supply cost: a round tool (weapon or terrain edit) that's
currently armed and becomes unaffordable — its own cost, or Supply drained by another purchase
— now auto-deselects instead of staying armed with a cursor preview the player can't actually
afford. Clicking an already-unaffordable tool no longer arms it either.

### Phase 6 — Terrain cost labels + terrain_edit unlock (user requests)

Raise Terrain / Lower Terrain / Reclaim Land now show their Supply cost the same way weapon
buttons do, and get the same dim/deselect treatment. Since terrain tools aren't
`config.STRUCTURES` entries, `BuildPalette.luau` gained a `costKey` field (alongside the
existing `typeId`) and a `toolCost(config, tool)` helper that reads either
`config.STRUCTURES[typeId].supply_cost` or `config[costKey]`.

Separately, user reported terrain editing felt blocked until a weapon was placed. Root cause:
`config.UNLOCK_TIME.terrain_edit` was a flat 20-second gate on live phase's elapsed clock,
unrelated to weapon placement but coinciding with it in practice (early weapon unlock times sit
in the same window). Set to `0` — terrain edit is now available from the instant live play
starts. `reclamation` stays gated at 60s (a separate, deliberately later-tier unlock the user
didn't ask about).
