# Session 008 — Real Two-Player Networking — Log

**Date:** 2026-09-17
**Branch:** session-008
**Type:** feature

## What was built

### Phase 1 — Shared replication contract

- Promoted `sim/view.luau` to `src/shared/view.luau`: the sim harness already had exactly
  the guarantee real client replication needed (a `View` carrying only round/board/owner/
  opponent and the calling player's own resources/structures/belief), so it became the
  network contract too instead of a second copy. `self` was extended to the owning
  player's entire player-state table (adding the score/stat fields the Result screen
  needs) rather than a hand-picked subset — still only ever the owning player's own
  fields. `sim/harness.luau` and `tests/view.spec.luau` now point at the shared copy.
- `src/shared/resolveView.luau` (new, tested): the per-owner animation payload — every
  shot from both sides, every structure destroyed, and misfire messages for a targeted
  weapon that produced no shot — ported from `PlanController:advanceRound()`'s old
  post-resolve logic so both the server and (indirectly, via the same shape) the client
  share one definition of "what one player is allowed to see about a round."
- `Rules.summary(config, playerState)` (new, in `rules.luau`): the Result screen's
  aggregate breakdown — counts and point totals only, never raw `structures`/`belief` —
  needed because the server can no longer hand a client the opponent's real structure
  list in the same payload that ends the match.

### Phase 2 — Server authority

- `server/MatchService.luau`: one real match's authoritative `MatchState` and round loop.
  Setup (base placement), PLAN-phase commands, and target assignment are all validated
  server-side through the same pure `State.*`/`Structures`/`Flight` functions the old
  client called directly — the client itself never mutates `MatchState` again. PLAN
  commands apply immediately (for a live push back to the same player) and queue in
  parallel for the round's real `Rules.resolveRound` replay, the same two-track model
  Session 007's local `PlanController` used. A round ends when both players ready up or
  the clock runs out, whichever comes first (own call — §4 didn't say; logged in
  `DECISIONS.md`).
- `server/CommandHandler.luau`: the `Command` remote's single entry point — a two-player
  matchmaking queue plus a per-player rate limit (20 commands/sec), then hands off to
  whichever `MatchService` a player is in.
- `server/Replication.luau`: shapes and fires every payload (`View` for state pushes,
  `ResolveView` for round animation, `Rules.summary` pair for match end) at exactly one
  player, never all clients.
- `src/shared/remotes.luau`: the `Command`/`StateUpdate`/`ResolveEvent`/`MatchFound`
  RemoteEvent set — server creates them at boot, client waits for them.
- `server/init.server.luau` wires `CommandHandler` to the `Command` remote and to
  `Players.PlayerRemoving`.

### Phase 3 — Thin client + practice mode split

- `PlanController.luau` rewritten from scratch as a thin server-driven view: every board
  action becomes a `Command` request; `self.state` (a `View`) only ever changes on a
  server `StateUpdate` push. Construction does a request-then-wait handshake so the first
  frame has real state to draw. The round clock shown client-side is now cosmetic —
  the server's own clock is what actually ends a round.
- The old local-only flow (client-held `MatchState`, scripted dummy opponent) moved
  unchanged to `PracticeController.luau`, kept as a documented fallback per the Open
  Gate decision. It now publishes a `View` of its private full state after every
  mutation so the shared UI layer (`StructureView`, `Cursor`, `Render`, `RoundClock`,
  `BuildPalette`) can stay blind to which controller is driving it.
- `StructureView.luau`, `Cursor.luau`, `Render.luau` updated to read `controller.state.
  self.*` (the `View` shape) instead of `controller.state.players[owner].*`.
- `Screens/Result.luau` rewritten to take a `{ own, opponent }` pair of `Rules.summary(
  ...)` tables instead of raw `MatchState` — the exploit check holds even at match end.
- `Screens/Intro.luau` gained a "Practice vs. Dummy" button and a waiting state for
  Start Game ("Waiting for opponent...").
- `UI/MatchController.luau` rewritten: "Start Game" queues on the server and waits for
  `MatchFound`; "Practice vs. Dummy" mounts instantly, no server round trip; Restart
  re-enters whichever of those the match that just ended came from.
- `UI/init.luau` (`PlanUI.mount`) takes a `mode` ("online"/"practice") and picks the
  matching controller; also now owns starting/stopping the camera per match (previously
  a single static `Camera.start("A")` in `init.client.luau`, which broke once the local
  player could be assigned "B").

## Deferred / carried forward

- No reconnection support — a disconnect mid-match just tells the remaining player and
  ends the match server-side. Out of scope for this session (§16 only asks for two
  clients able to play a match, not survive a drop).
- Restart after an online match re-queues into the general matchmaking pool rather than
  guaranteeing re-pairing with the same opponent (proposal §6.3 says "the same opponent
  configuration"). With exactly two players it re-pairs them in practice; not guaranteed
  with more than two in the queue. Worth a real "rematch" path if that ever matters.
- An incoming shot reveals its own firing weapon's position during the resolve
  animation (muzzle-flash-is-visible, scoped to only the weapons that fired) — a
  judgment call on a real tension between §12(f)'s exploit check and §13's "both
  volleys visible at once" resolve-phase spectacle. Logged in `DECISIONS.md`; the one
  place to tighten it later is `src/shared/resolveView.luau`.
- `PLAN_SECONDS`/weapon ranges are still testing-only values, unchanged this session,
  still pending §18's real balance pass.
