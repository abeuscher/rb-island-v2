# Session 020 — Sim Weapon Roles and Loadout Matrix — Log

**Date:** 2026-09-19
**Branch:** main
**Type:** feature

## What was built

### Phase 1 — Declared weapon roles and a generic Energy stand-down

Added `sim/loadout.luau`: a flat table (not one file per weapon type — mirrors
`config.STRUCTURES`'s own shape for 5 entries) declaring each weapon's category
(direct-damage / arc-finisher / recon / support-economy) and which categories it holds
fire for. `Kit.chooseTargets` (`src/shared/archetypeKit.luau`) gained an optional `holdFire`
parameter — a plain typeId set, no category concept in the shared layer — so a cheap weapon
(cannon) automatically skips its own turn once a costlier one (mortar/missile) exists *and*
a base or generator is actually plotted. This replaces `recon.luau`'s old inline
`hasMortar`/`focus` check and now applies to all seven archetypes via
`Loadout.holdFireSet`, not just recon. Kept in `sim/`, not promoted to `src/shared/` —
`server/Bot.luau` isn't part of this entry's scope, mirroring Session 016's own scout-on-bot
deferral (Open Gate decision).

### Phase 2 — Energy sizing derived from real weapon cost

Added `Kit.energySustainTarget(config, counts)`: generators needed to sustain continuous
fire from a `typeId -> count` table, computed from each weapon's real
`energy_cost`/`cooldown_seconds` against `ENERGY_PER_GENERATOR_PER_SECOND`. Every archetype's
`GENERATOR_TARGET` is now this formula applied to whichever weapons that archetype's own
doctrine already said it was sizing its economy around (cannons only for
highground/defilade/sprawl/rush; one mortar's worth for boomer/mortarline; the full
cannon+mortar+scout set for recon) instead of a hand-picked literal.

### Phase 3 — Missile and scout folded into existing archetypes, not new files

`recon` now builds and permanently flies a scout drone on recon duty (farthest unexplored,
falling back to farthest known) — a natural fit for an archetype whose whole doctrine is
already reconnaissance. `boomer`'s existing "mass-fire the priciest affordable weapon" spend
loop picked up missile ahead of mortar/cannon (matching `server/Bot.luau`'s own weapon
ordering). Both went in via the declared category system and each archetype's own existing
build pattern — no eighth/ninth archetype file.

### Phase 4 — Curated base-placement suite, and two real bugs it caught

Added `sim/placementSuite.luau` (wired into `lune run sim`): three curated layouts —
bases clustered in a corner, spread along one deep row, clustered deep-and-centered — run as
their own round robin alongside the normal `Kit.spreadPick` random spread, reporting per
archetype whether it ever found a base under each layout. `Kit.chooseBaseSpots` (new) is the
single seam every archetype's opening now calls through, so a curated layout needs zero
per-archetype code.

The first pass at this (bases pinned to the absolute back edge of the island) found that
5 of 7 archetypes *never once* found a base under any layout — investigated with a probe
script rather than accepted at face value, and turned out to be two distinct real bugs, not
balance noise:

- **`defilade` was placing its own cannons beyond their own range.** Its "tucked behind the
  ridge" cannon spot was the single backmost legal cell in its territory — 17-18 cells from
  the enemy at `CANNON_RANGE` 14, the exact same class of bug Session 019 found and fixed
  once already for a different cause. Fixed: the spot is now derived from `CANNON_RANGE`
  itself (a few cells behind the front, not the literal edge), so a future range change can't
  silently reintroduce it.
- **The curated layouts themselves were adversarial to the point of testing physics, not
  behavior** — pinned to the absolute edge of territory, past what even an elevated cannon or
  a frontline mortar could reach. Softened to 60% depth (`DEPTH_FRACTION` in
  `placementSuite.luau`): still meaningfully harder than the random spread, but within a
  plain unraised cannon's own range, so a miss is a real exploration gap rather than a range
  ceiling.

After both fixes, `base_elimination` share under the curated layouts rose from ~2-4% to
~58-60% (bases are actually being found and killed now), and no archetype shows a literal
0%-ever-found rate under any layout — the remaining variance (mortarline and sprawl miss
40-70% of the time; boomer/defilade/highground miss 20-55%) reflects real, expected doctrine
differences (mortarline has no cannon at all and unlocks its only weapon at t=40) rather than
a structural inability, and wasn't chased further — same call Session 019 made for
`defilade`'s own remaining weakness.

A third bug surfaced independently, from `lune run sim`'s purchase-share report rather than
the placement suite: **`boomer` never once bought a missile** across a full round robin,
even after Phase 3. Its `{missile, mortar, cannon}` spend loop drained Supply down to near
zero on mortar (always affordable first) every single decide() cycle, so missile's pricier
26-Supply threshold never had a chance to accumulate. Fixed by having the loop bank Supply
toward an already-unlocked pricier weapon instead of always grabbing whatever's cheapest and
affordable right now — a real behavior change (boomer now goes quiet on cannon/mortar
purchases while saving for a missile), confirmed against a batch of matches to actually
produce missile purchases afterward.

### Phase 5 — Test coverage and the intake checklist

`sim/` gained its first test coverage under `tests/`: `tests/sim.spec.luau` (a short-match
smoke spec per registered archetype — places its bases, fires at least one shot, has a
weapon in range of enemy territory; this is exactly what caught the defilade bug above) and
`tests/loadout.spec.luau` (the hold-fire rule's category/plotted-target logic), plus
additions to `tests/archetypeKit.spec.luau` for `energySustainTarget`, `pickNonOverlapping`,
`chooseBaseSpots`, and `chooseTargets`'s new `holdFire` parameter. Both follow
`tests/metrics.spec.luau`'s existing precedent — `sim/` is pure Luau, so no new runner was
needed.

README gained an "Adding a new weapon or structure to the sim" section: the intake checklist
(stats entry → declared role → derived Energy target → slot into a fitting archetype → run
the smoke test → confirm real usage in `lune run sim`), demonstrated end to end on missile
and scout rather than just asserted.

## Verification

- `lune run test`: 106/106 (89/89 at session start; 17 new specs).
- `lune run sim` (4,900-match round robin): `missile` and `scout` both show non-zero
  `purchaseShare` and were confirmed firing (160 and 1,067 shots respectively in a
  5-seed-per-pairing sample). No archetype shows zero shots fired. The curated placement
  suite ran as part of the same command and printed per-layout blind-spot breakdowns for all
  three layouts with no archetype at 0%-ever-found.
- `rojo build`: clean.
- `lune run sweep` was **not** run in full this session (each pass alone is ~15,000+ matches;
  the entry's success criterion only asks that it "still produce every metric," not a fresh
  balance pass) — confirmed instead that `sim/archetypes.luau`'s exported shape and the
  `Harness`/`Sweep` call surfaces sweep.luau depends on are unchanged, and exercised every
  archetype pairing directly through `Harness.runMatch` without error.

## Notes for next session

- `GENERATOR_TARGET` is now a derived number per archetype, sized against whichever weapons
  that archetype's own doctrine cares about (not literally everything it might ever build) —
  worth knowing before assuming these numbers are guesses like the old literals were.
- `boomer`'s weapon spend loop now saves up for a pricier unlocked weapon instead of always
  grabbing whatever's cheapest and affordable — a real behavior change from before this
  session, worth watching if a future balance pass revisits `boomer`'s win rate.
- If `CANNON_RANGE` or the board's `ISLAND_SIZE` ever changes again, `defilade`'s shielded
  cannon spot and `placementSuite.luau`'s `DEPTH_FRACTION` both derive from range/geometry
  rather than a hardcoded index — check they still land somewhere sane rather than assuming
  they're immune to a repeat of this session's bug.
