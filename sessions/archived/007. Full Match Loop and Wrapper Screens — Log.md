# Session 007 — Full Match Loop and Wrapper Screens — Log

**Date:** 2026-09-17
**Branch:** session-007
**Type:** feature

## What was built

### Phase 1 — Setup phase and real command batching

- `PlanController` gained a fourth phase ahead of PLAN/RESOLVE: `"setup"`, untimed. Each
  side places exactly `NUM_BASES` (3) bases before rounds can start; the dummy's are seeded
  directly and instantly (it has no build phase to wait through), the player's go through
  the normal `State.placeStructure` validation via a restricted `BuildPalette` tool set
  (base + bulldoze only, weapon list hidden). Ready is gated on the count and, once
  satisfied, completes construction on whatever's placed and starts round 1's clock.
- Adopted `Rules.resolveRound`'s command-batch model, closing the gap Session 006
  deliberately left open. PLAN-phase actions still apply immediately to `self.state` for
  live board feedback (same precedent as Sessions 005-006), but are now also logged to
  `pendingCommands` in parallel. At round's end those commands are replayed from a
  `roundStartState` snapshot through `Rules.resolveRound` alongside the dummy's own
  scripted per-round command (`_dummyCommandsForRound`), so both sides resolve
  simultaneously against the same pre-round state — the real batching `resolveRound` was
  built for. `rules.luau` now also returns a fourth `resolution` value (pre-combat state
  plus each side's raw shots/destroyed lists) so the client can still animate precisely
  without duplicating resolveRound's internal orchestration.
- Caught and fixed a real divergence this surfaced: the immediate-apply preview didn't
  know `resolveRound` silently drops a structure placed on a cell terrain-edited the same
  round (§8, already tested in `rules.spec.luau`). Added the same guard client-side so a
  placement that will be dropped at resolve is now also rejected immediately, with a clear
  message, instead of showing a structure that later vanishes.
- `Board.islandBounds(config, owner)` added — each player's starting-island rectangle,
  derived from config alone, so the dummy's structures can be placed at safe, non-
  overlapping coordinates without walking every owned cell.

### Phase 2 — Wrapper screens and match lifecycle

- Three screens under `src/client/UI/Screens/`: `Intro` (Start Game enabled, Save Game and
  Continue rendered-but-disabled, Settings), `Settings` (title + close button, renders
  whatever `SettingsRegistry.luau` contains — empty for now, so an empty panel), and
  `Result` (winner + plain-language condition, a side-by-side itemized breakdown per
  player, Restart).
- `MatchController.luau` owns the intro → setup → rounds → result state machine. Each
  Start Game or Restart mounts a fresh `PlanUI` (board, HUD, `PlanController`) and tears
  the previous one down — `PlanUI.mount` now returns `{ controller, teardown }` rather than
  a bare controller, with all of a match's Workspace folders under one `Match` folder and
  its Input/Cursor connections captured for clean teardown. Restart never needs a rejoin.
- Score/stat bookkeeping needed by the Result screen didn't exist yet: `structuresBuilt`,
  `shotsFired`/`shotsHit`/`shotsBlocked`, and `destructionPointsByType` added to player
  state, accumulated inside `resolveRound` (shot "hit" is tracked per shot from its primary
  impact-cell damage event). Standing points by type are cheap enough to compute directly
  from the final structures list at Result-render time instead of tracking incrementally.
- `base` had no placeholder color/glyph in `StructureView.luau`/`Render.luau` (it was never
  a placeable structure before this session) — added both.

### Phase 3 — User feedback from live testing

- Ready button now gets a white `UIStroke` outline once setup's base count is satisfied,
  to call attention to it. First pass stroked the button's *text* rather than its border —
  `UIStroke.ApplyStrokeMode` defaults to `Contextual`, which outlines text glyphs on a
  text-bearing object; fixed by setting it to `Border`.
- Scoring only rewarded destruction and standing (structures still alive at match end) —
  a real balance complaint surfaced live: losing on points despite out-scouting the
  opponent (2 of their 3 bases found) because they'd simply built one more structure.
  Added two new `POINTS` categories: `reveal` (once per enemy structure the first time
  it's sighted — by a direct hit or just a cannon's beam passing over it) and `hit`
  (landing damage, separate from and in addition to a kill). Values are ~20%/~10% of a
  kill's worth, the same "guess pending a real balance pass" caveat as every other number
  in that table. A structure only pays reveal points once per sighting (compares the whole
  belief map before/after each round's reveals, not per-shot) — rebuilding or re-revealing
  something already known doesn't farm points again.

## Verification

`lune run test` green throughout, 76/76 by the end (up from 71 at Session 006's close: 3
new tests for `Board.islandBounds`, `resolveRound`'s hit/reveal point accumulation and its
raw resolution return value, plus one for `structuresBuilt`). `rojo build` clean after
every phase. New/changed client files smoke-tested by running them directly under
`lune run` — each fails only on the expected missing Roblox globals (`game`), not a parse
error, same convention as prior sessions.

The user tested live and drove both Phase 3 fixes: the Ready-button highlight (twice — the
first pass had the right idea but the wrong `UIStroke` mode) and the reveal/hit points
addition, from an actual lost match where the scoring felt wrong.

## Deferred / carried forward

- `PLAN_SECONDS` (10) and both weapons' ranges (cannon 20, mortar 32) are still testing-only
  values, not balance-considered — unchanged this session, still pending §18's real tuning
  pass alongside the sim harness's shortlist.
- The new `reveal`/`hit` point values are a first guess, not validated against play — worth
  revisiting once there's more match data, likely alongside the existing `POINTS.destroy`/
  `standing` sweep candidates.
- No visual confirmation yet of the Result screen's layout/wording at a real 1080-ish
  resolution, or of the Settings panel (still empty, so low-stakes) — worth a glance next
  time Studio's open.
- Cursor.luau's live placement-preview doesn't know about the same-round terrain-edit
  guard added this session (PlanController's actual click handling does) — a narrow edge
  case (raise/lower/reclaim a cell, then try to place on it the same round) where the
  cursor preview would show green for a placement that gets rejected on click. Real bug,
  small enough to leave for a future pass rather than block this session on it.
