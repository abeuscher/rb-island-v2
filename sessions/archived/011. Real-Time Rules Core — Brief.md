# Session 011 — Real-Time Rules Core — Brief

**Type:** feature
**Shape:** plan-backed
**Branch:** session-011

## Goal

Replace `src/shared/rules.luau`'s batch `resolveRound` with a tick-evaluated real-time
core: per-weapon fire cooldowns, rate-based Supply/Energy accrual, immediate terrain/
structure commands, timed (`readyAt`) construction, and a single match clock in place of
`MAX_ROUNDS` — fully covered by a rewritten Lune test suite, headless and pure.

## Plan reference

This session executes the plan file's entry for **Real-time rules core**
(`sessions/plan.md`). Read that entry first — it is canonical for scope, success criterion,
prerequisites, and artifact, including the fixed-tick decision (0.5s default, config-driven)
made in Session 010.

## Session-specific deltas

- Session 010's planning pass found that `resolveRound` doesn't cleanly separate "apply this
  round's commands / run the RESOLVE step order" from "scoring and incapacitation math" —
  they're interleaved in one function (`src/shared/rules.luau:366-510`). This session is a
  re-plumbing of the batch-resolution engine into a tick function, not a redesign of what
  gets scored — keep `Rules.finalScore`, `Rules.summary`, the destroy/reveal/hit point
  bookkeeping, and the incapacitation checks (`isIncapableNow`/`isUnrecoverable`) close to
  as-is, restated in time terms (an incapacitation streak measured in elapsed seconds/ticks
  rather than rounds) rather than rewritten from scratch.
- `state.luau`'s `round` counter and `State.completeConstruction`'s "both sides ready up"
  model both need real replacements (`readyAt` timestamps, elapsed match time), not just a
  rename — read `state.luau` in full before touching it.
- `economy.luau`'s `Economy.accrue` is currently a per-round lump function called once per
  `resolveRound`; converting it to a per-tick rate means deciding whether the tick loop calls
  it every tick with a smaller per-tick amount, or accrues continuously via a rate × elapsed-
  time calculation evaluated on read. Either is defensible — pick one, note why, don't spend
  a design pass on it.
- This entry has no other in-progress plan.md entries depending on it being partially done —
  it's safe to take as much of this session as it needs; entries 2-5 all wait on it finishing
  cleanly rather than on a specific cutoff.
