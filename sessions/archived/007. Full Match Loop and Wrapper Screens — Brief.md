**Type:** feature

## Goal

Build multi-round progression with unlock gates and a running economy working end to end
through a real session state machine (intro → setup → rounds → result), with the three
wrapper screens from the proposal's §6.

  there is no `src/server/` code at all yet beyond scaffolding — Sessions 004–006 built
  everything client-local (see Starting state). Deciding how much server-authority to pull

  gap most plausibly gets closed, once there's a real second player (even if still

## Starting state

- PLAN and RESOLVE both work client-locally against a static, hardcoded dummy opponent
  seeded onto the enemy island (Session 006) — there's still no real second player, no
  server, and no setup phase.
- `base` is still absent from the build palette (per §8, bases are placed during a setup
  phase that doesn't exist until this session, not bought with Supply during PLAN).
- `PlanController` applies every PLAN-phase command immediately as the player clicks
  (`State.placeStructure` etc.), not batched. `rules.luau`'s `resolveRound` expects a
  batch of commands per side. Reconciling these is likely this session's biggest single
  piece of work.
- No score/points bookkeeping (`destructionPoints`, `structuresLost`) is wired into the
  local state yet — `Rules.finalScore` and the standing-points computation exist in
  `rules.luau` but have never been called from client code.
- `PLAN_SECONDS` is currently 10 and both weapons' ranges are doubled (cannon 20, mortar
  32) — testing-only values from Session 006, not a balance decision. Leave them as-is
  unless they get in the way; §18 flags real tuning as work for later, alongside the sim
  harness's shortlist.
- The housekeeping inbox is empty; nothing to absorb this session.

## Open questions

- **How much server authority to pull forward.** The plan entry's artifact names
  `server/MatchService.luau`, but §12 (server authority) is squarely the next-next plan
  entry's (**Real two-player networking**) job, and every prior UI session has stayed
  local-only by precedent. Worth deciding explicitly at the Open Gate: keep the state
  machine and all three screens local-only for now (mirroring Sessions 004–005), or start
  shaping `MatchService` as a real server module even before real networking exists.
- **Whether to adopt `rules.luau`'s `resolveRound` batch now**, replacing
  `PlanController`'s immediate-apply command model, or keep extending the direct-call
  approach from Session 006. This is a good moment to close that gap since a real setup
  phase and multi-round loop are exactly what `resolveRound` was built for — but it's a
  genuine rework of how `PlanController` tracks pending commands, not a small delta.
