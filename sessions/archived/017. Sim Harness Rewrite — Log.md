# Session 017 — Sim Harness Rewrite — Log

**Date:** 2026-09-18
**Branch:** main
**Type:** feature

## What was built

### Phase 1 — `sim/harness.luau`: round-batch → time-stepped

Replaced the dead `Rules.resolveRound(config, state, commandsA, commandsB)` call (removed in
Session 011) with the real split API: each archetype's `decide()` runs once at `elapsed == 0`
(base placement + opening buys), then `Rules.tick(config, state)` steps the match forward every
`config.TICK_SECONDS`, with `decide()` re-run on `config.BOT_DECIDE_INTERVAL_SECONDS` — the same
periodic cadence `server/Bot.luau` already uses during live play — instead of once per round.
Commands apply immediately via `Rules.applyCommand`, one at a time, matching how a real client's
commands are handled now.

Found on first run: freshly placed structures start `underConstruction` (a real build timer, not
instant-complete-at-round-end like the old model), so every match was ending in instant
`base_elimination` — `checkVictory` saw zero live bases on the very first tick. Fixed by calling
`State.completeAllConstruction` right after the opening `decide()` call, mirroring
`MatchService`'s own setup → live transition (bases were never meant to sit on a build timer).

Simplified `recordShots` to read `typeId`/`blocked` straight off `Rules.tick`'s own
`resolution.shotsA`/`shotsB` (which already carry the firing weapon's `def` and resolved shot),
dropping the old per-round cell → typeId lookup table entirely — it existed only to reconstruct
information the new resolution payload already has for free.

### Phase 2 — Archetype round → time renames

All five (`highground`, `defilade`, `boomer`, `mortarline`, `sprawl`): `view.round == 1` →
`view.elapsed == 0`; `config.UNLOCK_ROUND.terrain_edit`/`.reclamation` → `config.UNLOCK_TIME.*`;
`def.unlock_round` → `def.unlock_time`; `mortarline`'s `config.UNLOCK_ROUND.mortar` (a stale
flat-key lookup that never matched `config.STRUCTURES.mortar.unlock_time`'s real shape even
before Session 011) corrected to `config.STRUCTURES.mortar.unlock_time`, same pattern
`server/Bot.luau` already uses. Same class of dead-reference bug Session 015 fixed in `Bot.luau`.

### Phase 3 — `sim/metrics.luau` / `report.luau`: metrics re-derived in time terms

`rounds`/`firstBaseFoundRound`/`scoreByRound` → `duration`/`firstBaseFoundAt`/`scoreOverTime`.
`comebackRate` now indexes the midpoint off `#scoreOverTime` (one entry per tick) instead of a
round count. `round_limit` → `time_limit` throughout. Time-keyed durations land on whatever
second a tick happened to end a match on rather than a handful of small round numbers, so
`matchLengthDistribution`/`timeToFirstBaseDistribution` bin to 10-second buckets — without this
the report exploded to one row per distinct elapsed value (confirmed on the first real run: over
200 rows), instead of the ~20 rows the old round-based histograms had.

### Phase 4 — `sim/sweep.luau` / `.lune/sweep.luau`

`roundLimitShare`/`conditions.round_limit` → `timeLimitShare`/`conditions.time_limit`. Sweep
dimension names updated to their real config keys: `SUPPLY_PER_ROUND` → `SUPPLY_PER_SECOND`,
`ENERGY_PER_GENERATOR` → `ENERGY_PER_GENERATOR_PER_SECOND`, `MAX_ROUNDS` → `MATCH_SECONDS`; test
values rescaled by the ~20s-per-round factor `config.luau`'s own comments already establish for
this exact port (per-round values ÷20 for per-second rates, ×20 for `MATCH_SECONDS`).

Found and fixed a second real bug, independent of the round→time port: the `generatorHeavy`
`POINTS_PRESET` replaced `config.POINTS` wholesale with a literal frozen at Session 003 — missing
the `reveal`/`hit` categories Session 007 added and the `missile`/`scout` entries Session 016
added. Crashed (`attempt to index nil with 'base'`) the instant anything got revealed during
Pass 3 of a real sweep run. Fixed by mutating the existing, already-complete `config.POINTS`
table in place (`config.POINTS.destroy.generator = 50`, `.standing.generator = 20`) instead of
replacing it — removes the separate hand-maintained literal entirely, so it can't drift out of
sync with the roster again.

### Phase 5 — `tests/metrics.spec.luau`

Rewrote test-for-test against the renamed fields/functions (`timeToFirstBaseDistribution`,
`scoreOverTime`, `firstBaseFoundAt`, `duration`, `time_limit`), including a bucketing-aware
assertion for the new 10-second binning.

## Scoping call (per the brief's Open Gate)

Missile and scout stayed out of the five sim archetypes — cannon/mortar only, matching the real
bot's own scout-drone deferral from Session 016. Nothing in the round→time port depended on
them; folding in two more weapon types was extra scope beyond the rewrite's own success
criterion. User confirmed at the Open Gate.

## Mid-session addition

User raised a design issue live: the cannon (direct fire, full beam reveal) reveals more ground
than the scout drone (arc fire, 5-cell impact reveal — identical to mortar/missile), which is
backwards for a dedicated recon weapon. Proposed fix (3-wide trail + 4x4 block at target) was
scoped and written up as a new plan-file entry, **not implemented** — out of this session's scope.
See "Scout drone reveal shape" in the plan file.
