# Session 012 — MatchService Real-Time Loop — Brief

**Type:** feature
**Shape:** plan-backed
**Branch:** session-012

## Goal

Collapse `server/MatchService.luau`'s `setup → plan → resolve → result` phase machine into
`setup → one live phase (driving Session 011's `Rules.tick`) → result`, drop the old
immediate-apply/replay two-track command model, and rework `server/Replication.luau`'s push
shape for a continuous tick instead of a per-round batch.

## Plan reference

This session executes the plan file's entry for **MatchService real-time loop**
(`sessions/plan.md`). Read that entry first — it is canonical for scope, success criterion,
prerequisites, and artifact.

## Session-specific deltas

- Session 011 replaced `Rules.resolveRound(config, state, commandsA, commandsB)` with two
  separate entry points: `Rules.applyCommand(config, state, owner, cmd)` (one command, applied
  immediately and permanently — place/bulldoze/raise/lower/reclaim/target) and
  `Rules.tick(config, state)` (advances the match by one `config.TICK_SECONDS` heartbeat:
  construction, automatic cooldown-gated weapon fire, income, incapacitation, victory). A
  weapon's target now persists on the structure itself (set once via a `target` command,
  fires on its own whenever off cooldown) instead of needing to be resent every round —
  `CommandHandler`/`MatchService` no longer need to replay a player's PLAN-phase batch at a
  resolve boundary, since there isn't one.
- `state.round` is gone; `state.elapsed` (seconds) replaces it. `src/shared/view.luau`'s
  `View.new` was updated to match (`round` → `elapsed` field) since it's the shape a client is
  allowed to see over the network (§12) — read it if you need the exact contract.
- `src/shared/resolveView.luau` (Session 008's per-round animation-view shim, consumed by both
  `MatchService.luau` and `Replication.luau`) was deleted in Session 011 as obsolete under
  continuous ticks rather than patched — this session needs its replacement: something that
  shapes `Rules.tick`'s per-tick `(events, victory, resolution)` into whatever the client needs
  to animate shots/damage/reveals as they happen, scoped to §12's guarantee (a client never
  receives an unrevealed enemy structure in any payload).
- `src/client/UI/PracticeController.luau` (the local-only "Practice vs. Dummy" flow) also calls
  `Rules.resolveRound` directly and is not named in this entry's artifact list or in "Client
  real-time UI"'s (entry 4's) either — it's a real gap between the plan's entries, not
  something already assigned. Decide at the Open Gate whether it's in scope here (it's the
  same server-authority-free local flow MatchService's rework doesn't otherwise touch) or
  explicitly deferred to a later entry, and say which.
- `server/Bot.luau` and `sim/harness.luau` also call the old round-based API but are entries 3
  and 5's scope respectively — expected to stay broken through this session.
