# Session 018 — Scout Drone Reveal Shape — Brief

**Type:** feature
**Shape:** plan-backed
**Branch:** main

## Goal

Give the scout drone a reveal shape that actually fits its job: a 3-wide corridor along its
flight path plus a 4x4 block at the target, instead of sharing the mortar's plain 5-cell impact
reveal, per the plan file's "Scout drone reveal shape" entry.

## Plan reference

This session executes the plan file's entry for "Scout drone reveal shape". Read that entry
first — it is canonical for scope, success criterion, prerequisites, and artifact.

## Session-specific deltas

- This came out of a live conversation during Session 017 (not from `sessions/proposal.md`), so
  there's no spec section to cross-check — the plan entry's success criterion is the full spec.
- Exact shape questions the plan entry leaves open for this session's judgment: whether the 4x4
  target block is centered on the target cell or anchored some other way (a 4x4 has no true
  center on a grid — pick a reasonable anchor and note the call), and how the corridor handles a
  target that's diagonal vs. orthogonal from the firing cell (reuse `flight.luau`'s existing
  `beamCells` stepping if it fits, rather than inventing a second line-walking algorithm).
- The scout drone deals 0 damage and never blocks on terrain (Session 016) — this entry is fog
  computation only, nothing about `Rules.tick`'s combat/damage path changes.

## Starting state

- The scout drone (Session 016) is a real, playable, non-damaging `config.STRUCTURES` entry;
  everything about targeting/cooldown/firing is generic and already works. Only its reveal
  shape is undersized relative to its purpose.
- `reveal_mode` (`"beam"` for cannon, `"impact"` for everything else) already exists per-weapon
  in `config.luau` but `Fog.revealedCells` doesn't read it — it branches on `fire_mode` instead,
  which is why every arc weapon (mortar/missile/scout alike) currently shares the same 5-cell
  reveal shape.
- `Fog.applyReveal(config, board, structures, belief, def, shot, destroyedThisRound)` has no
  origin parameter today; `rules.luau`'s caller already holds the firing weapon's origin cell
  (`firing.origin` in `planShots`/`applyFirings`, `s.origin` in the `shots` list `Rules.tick`
  builds) and will need to pass it through.

## Out of scope

- Any change to the cannon's beam reveal or the mortar/missile impact-plus-neighbors reveal —
  both stay exactly as they are; only the scout gets a new shape.
- Damage, targeting, or cooldown behavior — this is fog computation only.
- Board-size changes. The plan entry notes the corridor/block sizing should be revisited if the
  island is ever enlarged, but that's a future concern, not this session's.
