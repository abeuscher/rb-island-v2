### Phase 2 — New shared module: tickView.luau

Added `src/shared/tickView.luau` (+ spec) as the per-tick replacement for Session 008's
`resolveView.luau` (deleted last session): same redaction shape (an owner's own shots plus
enemy shots that hit them, destroyed structures from both sides, per DECISIONS.md's "an
incoming shot reveals its own firing weapon's cell" call), minus the misfire-explanation
concept a per-round PLAN commitment needed -- a weapon that can't fire this tick just tries
again next tick, with no round boundary to explain itself at.

### Phase 3 — Replication.luau and remotes.luau

Consolidated `pushState`/`pushResolveView` into one `pushState` call: fired after a command
(with `message`/`ok`) and once per tick (with a `tickView` carrying whatever landed to
animate) -- never both at once. Removed the now-unused `ResolveEvent` remote from
`remotes.luau`'s registry.

### Phase 4 — MatchService.luau

Collapsed `setup → plan → resolve → result` to `setup → live → result`. `live` runs a
`task.spawn` loop calling `Rules.tick` every `config.TICK_SECONDS` and pushing the result to
both players; every command applies immediately via `Rules.applyCommand`/`_applyAndPush`
instead of MatchService's own hand-rolled per-type State.* dispatch. Removed
`pendingCommands`, `roundStartState`, `targets`, the same-round terrain-edit conflict check,
and the per-round `task.delay` timer entirely. Kept the existing target-command
range/ownership preflight (instant error messages) ahead of `Rules.applyCommand`'s own
lazier fire-time check, for UX parity with before. `server/Bot.luau`'s `decide()` is still
broken from Session 011's config renames (`view.round`, `config.UNLOCK_ROUND`) -- out of
scope (Bot re-adaptation's entry) -- so the live tick loop is now started *before* the bot's
one-shot decide() call, not after, so a bot-seat error can't take the whole live loop down
with it. `CommandHandler.luau` needed no changes; it was already phase-agnostic.

### Phase 5 — Client: PlanController.luau, RoundClock.luau, Cursor.luau

Rewrote `PlanController.luau` to match: one `StateUpdate` handler instead of two separate
remotes, `onResolve` now fires only when a tick actually has shots/destroyed to animate
(guards against `Render.luau`'s `effectsFolder:ClearAllChildren()` cutting off an in-flight
shot animation on an empty tick, since `TICK_SECONDS` (0.5s) is shorter than a shot's travel
time), and the local per-round countdown clock is gone -- elapsed time reads straight off the
server's continuously-pushed `view.elapsed`. `RoundClock.luau` got the minimal fix the brief
called for (phase branches, hides Ready once live) -- not entry 4's real redesign.
`Cursor.luau` had a real bug found on read: `controller.state.round` passed into
`Structures.canPlace`'s elapsed-time param, which would have errored on every placement-tool
hover -- fixed to `controller.state.elapsed`.

### Phase 6 — Live bug: setup bases never went live

User's first live test failed: the game jumped from the end of setup straight to a result
screen, as if the tick loop never started. Root cause: `Structures.completeConstruction`
(gated last session on `elapsed >= readyAt`, for a real live-play build timer) was still
being called at the setup -> live transition -- but setup-placed bases were stamped
`readyAt = elapsed(0) + BUILD_SECONDS`, and elapsed was still 0 at that exact moment, so
`completeConstruction` did nothing. Both sides showed zero live bases on the first tick,
which reads as simultaneous mutual base elimination -- instant game over. Setup bases were
never meant to sit on a build timer at all (placed and standing before live begins, per the
design doc). Fixed by adding `State.completeAllConstruction` (completes every structure
regardless of `readyAt`, via `Structures.completeConstruction(config, list, math.huge)`),
used only at the setup -> live transition; the tick loop's own per-tick call stays
time-gated for anything actually built during live play. Covered by a new state.spec.luau
test. User re-tested live and confirmed the tick loop and match now work as expected.
